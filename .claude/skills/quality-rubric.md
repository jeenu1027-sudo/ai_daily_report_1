## Summary

프로젝트의 **견고성과 신뢰성**을 객관적으로 평가하는 종합 루브릭입니다.

5가지 핵심 항목을 **5단계(Excellent/Good/Acceptable/Needs Work/Broken)**로 평가하여 종합 등급을 산출합니다.

---

## Rubric Items (5개 항목)

### 1️⃣ 필터링 정확도 (20% 가중치)

필터링 규칙의 정확도와 효과 측정 능력

| Level | 기준 |
|-------|------|
| 🟢 Excellent (85+) | 6가지 규칙 100% 준수, 거짓양성/음성 < 2%, 품질 점수 시스템 |
| 🔵 Good (75-84) | 규칙 95%+ 준수, 거짓양성/음성 2-5%, 효과 측정 가능 |
| 🟡 Acceptable (60-74) | 규칙 80-94% 준수, 스팸/노이즈 인식 가능 |
| 🟠 Needs Work (40-59) | 규칙 80% 미만, 명백한 필터링 실패 |
| 🔴 Broken (<40) | 필터링 규칙 미작동 |

**평가 포인트:**
- 필터링 규칙 준수율
- 가양성/음성 비율
- 품질 점수 계산 로직 구현
- 필터링 효과 측정 기능

---

### 2️⃣ 리포트 품질 (20% 가중치)

생성되는 리포트의 시각성, 가독성, 기능성

| Level | 기준 |
|-------|------|
| 🟢 Excellent (85+) | HTML 100% 정상, 한글 완벽 지원, 모바일 반응형, 다크모드 |
| 🔵 Good (75-84) | 대부분 정상, 일부 UI 미흡, 반응형 양호 |
| 🟡 Acceptable (60-74) | 기본 렌더링 가능, 텍스트 가독성 OK |
| 🟠 Needs Work (40-59) | 렌더링 오류 있음, 가독성 문제 |
| 🔴 Broken (<40) | 리포트 생성 실패/열 수 없음 |

**평가 포인트:**
- HTML 렌더링 정상도
- 한글 완전 지원
- 모바일 반응형 구현
- 다크모드 지원
- 인쇄 최적화

---

### 3️⃣ 자동화 신뢰성 (20% 가중치)

자동화된 실행의 안정성과 신뢰성

| Level | 기준 |
|-------|------|
| 🟢 Excellent (85+) | 매일 8시 100% 성공, 재시도 정책, 로깅/모니터링 |
| 🔵 Good (75-84) | 95%+ 성공률, 재시도 로직 있음 |
| 🟡 Acceptable (60-74) | 80-94% 성공률, 수동 개입 필요 시기 있음 |
| 🟠 Needs Work (40-59) | 80% 미만 성공률, 자주 실패 |
| 🔴 Broken (<40) | 자동화 미작동 |

**평가 포인트:**
- 자동 실행 성공률
- 재시도 로직 (exponential backoff)
- 로깅 메커니즘
- 에러 알림 기능
- 배치/스케줄 파일 품질

---

### 4️⃣ 코드 품질 (20% 가중치)

코드의 유지보수성, 안정성, 테스트 커버리지

| Level | 기준 |
|-------|------|
| 🟢 Excellent (85+) | 타입힌팅 100%, 테스트 >80%, 명확한 구조 |
| 🔵 Good (75-84) | 타입힌팅 대부분, 테스트 60-80%, 이해하기 쉬움 |
| 🟡 Acceptable (60-74) | 기본 구조 있음, 테스트 40-60%, 일부 기술부채 |
| 🟠 Needs Work (40-59) | 타입힌팅 부족, 테스트 <40%, 복잡한 구조 |
| 🔴 Broken (<40) | 심각한 기술부채, 테스트 거의 없음 |

**평가 포인트:**
- 타입힌팅 적용도
- 테스트 커버리지
- 에러 처리 구체성
- 코드 가독성
- 함수 단위 설계

---

### 5️⃣ 문서화 (20% 가중치)

문서화 수준과 개발자 경험(DX)

| Level | 기준 |
|-------|------|
| 🟢 Excellent (85+) | README 완벽, API 문서화, 스킬 문서 완전 |
| 🔵 Good (75-84) | 주요 기능 문서화, 스킬 사용법 설명 있음 |
| 🟡 Acceptable (60-74) | 기본 설명만 있음, 일부 미흡 |
| 🟠 Needs Work (40-59) | 문서 부족, 설정 방법 불명확 |
| 🔴 Broken (<40) | 문서 거의 없음 |

**평가 포인트:**
- README 완성도
- API 문서화
- Docstring 포함도
- 예시 코드 충실도
- 설정 가이드

## Scoring Algorithm

### 최종 점수 계산

```
최종 점수 = (필터링×20% + 리포트×20% + 자동화×20% + 코드×20% + 문서×20%)
```

### 등급 판정

| 점수 | 등급 | 의미 |
|------|------|------|
| 85-100 | 🟢 Excellent | 프로덕션 준비 완료 |
| 75-84 | 🟢 Good | 주요 기능 양호, 개선 가능 |
| 60-74 | 🟡 Acceptable | 기본 작동, 개선 필요 |
| 40-59 | 🟠 Needs Work | 명백한 문제, 즉시 개선 필요 |
| <40 | 🔴 Broken | 심각한 결함, 사용 불가 |

## Usage Examples

### 프로젝트 초기 평가

```
필터링 정확도: 70/100 (🟡 Acceptable)
  - 필터링 규칙 기본 구현
  - 효과 측정 불가
  - 품질 점수 미구현

리포트 품질: 88/100 (🟢 Excellent)
  - HTML 렌더링 우수
  - 한글 완전 지원
  - 모바일 반응형

자동화 신뢰성: 65/100 (🟠 Needs Work)
  - 로깅 없음
  - 재시도 로직 없음
  - 배치 파일 기본 수준

코드 품질: 72/100 (🟡 Acceptable)
  - 타입힌팅 없음
  - 테스트 거의 없음
  - 에러 처리 미흡

문서화: 85/100 (🟢 Good)
  - README 완전
  - 스킬 문서 상세
  - API 문서 부족

전체 등급: 77/100 (Good)
```

### 개선 후 최종 평가

```
필터링 정확도: 82/100 (🟢 Good)
  + 품질 점수 함수 구현
  + 필터링 효과 측정 추가
  + 가양성/음성 추적

리포트 품질: 90/100 (🟢 Excellent)
  + 품질 점수 표시

자동화 신뢰성: 87/100 (🟢 Excellent)
  + 로깅 인프라 구축
  + Exponential backoff 재시도
  + .bat/.ps1 개선

코드 품질: 85/100 (🟢 Good)
  + 타입힌팅 100% 적용
  + 단위 테스트 추가 (25개)
  + 에러 처리 구체화

문서화: 88/100 (🟢 Good)
  + Docstring 추가
```

## Integration with Harness

### 연동 에이전트

- **morning-briefing**: 일일 리포트 생성 시 품질 평가
- **quality-assessor** (신규): 주간/월간 품질 평가 에이전트

### 자동 평가 워크플로우

```
1. news-fetcher-agent 실행
   ↓
2. quality-rubric 평가 (필터링 정확도)
   ↓
3. report-generator 실행
   ↓
4. quality-rubric 평가 (리포트 품질)
   ↓
5. 최종 점수 계산 & 리포트 생성
```

## Maintenance

### 평가 기준 검토 주기

- **월 1회**: 필터링 규칙 검토
- **분기 1회**: 전체 루브릭 검토
- **반기 1회**: 가중치 조정 검토

## Quality Metrics Reference

```python
metrics = {
    'filter_rate': 0.45,              # 필터링 비율
    'avg_quality_score': 82.3,        # 평균 품질 점수
    'false_positive_rate': 0.02,      # 거짓양성률
    'false_negative_rate': 0.03       # 거짓음성률
}
```

### 자동화 신뢰성 측정

```python
metrics = {
    'success_rate': 0.98,             # 성공률
    'avg_response_time': 12.5,        # 평균 응답시간 (초)
    'last_30_days_failures': 1,       # 지난 30일 실패 횟수

}
```
